# Quality rubric and learning loop

## Review rubric (private, scored before delivery)
Score each criterion from 1 to 5. Revise if any criterion is below 3, or if the average is below 4. Show the scores only when the user asks.

| Criterion | 5 looks like | 1 looks like |
|---|---|---|
| Persona relevance | A coach in the target segment thinks "that's my evening" | Could be about any profession |
| Problem specificity | One concrete, recognisable situation | A vague theme |
| Practical usefulness | The reader can do something better today | Only motivation or promotion |
| Natural Persian | Sounds like a knowledgeable colleague, with correct half-spaces | Translated or AI-sounding, with clichés |
| Credibility and evidence | Claims trace to product-claims, interviews or cited sources. Hypotheses are labelled. | Invented numbers, quotes or capabilities |
| Brand alignment | Calm, confident, respects the coach. Tech supports, the coach decides. | Hype, shame, "AI replaces you" |
| Opening strength | Specific and curious from the first line or second | A generic or banned opener |
| Platform fit | Follows the channel structure and length | Wrong structure for the channel |
| CTA clarity | One CTA matched to the objective | None, or several competing CTAs |
| No unsupported claims | Nothing unverified, prices are placeholders, Pro is flagged | Any fabricated or ⚠️ feature presented as live |

Quick red flags (fix them on sight):
- «هوشمند» or «هوش مصنوعی»
- a percentage or time saving
- a quote marked as said by a coach
- a library size
- a price
- «تا حالا به این فکر کردی»
- two or more CTAs
- a product pitch inside a piece meant to be education-only

## Performance analysis
When the user shares metrics:
1. Split the layers: reach (views, impressions) · qualified engagement (saves, shares, meaningful comments, replies from coaches) · product interest (link clicks, profile visits, DMs about the app) · signup · activation (first program sent) · repeat use · paid · referral.
2. Name the audience problem and objective each piece targeted.
3. Compare only like with like: same format, same objective, similar timing.
4. Small samples are noisy. Use "suggests" or "worth testing", not "caused". Note confounders such as posting time, boosting, or a collaboration.
5. Judge each piece against **its own objective**. A Reel with high views but no activation signal isn't an activation success.
6. Recommend **one or two** concrete experiments, each with a hypothesis, a variable, a metric and a sample or time frame.
7. Append the learning to `learning-log.md`: date, what was tested, result, confidence, next step.

## New interviews
1. Keep the raw notes private. Don't paste identifiable details into public content.
2. Pull out **direct statements**, marked as quotes only if they're verbatim, separately from **your interpretation**.
3. Tag each pain point, motivation, barrier and language item as new, confirmed (repeated), or contradicting the existing persona.
4. Keep minority or distinctive needs. Don't average them away.
5. Update `persona-evidence.md` only when the evidence justifies it, for example a pain point repeated across interviews. Change [H] to [O] with a source ID. Never overwrite the original observations with generalisations.
6. Log every persona change, with its evidence, in `learning-log.md` and in the persona file's change history.
7. If a coach suggests a product feature, check `product-claims.md` to see whether it already exists. If it exists, that points to a discoverability or communication gap, which is a content opportunity.
